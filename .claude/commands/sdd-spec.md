새 기능 명세를 작성한다. 요청: $ARGUMENTS

## 절차

1. **조사** — `CLAUDE.md`, `docs/product.md`, 기존 `specs/`, 관련 소스 코드를 읽는다. 이 기능과 겹치거나 재사용할 수 있는 것을 찾는다.
2. **트랙 결정** — 인자에 `--lite`·`--full`이 있으면 따른다. 없으면 아래 기준으로 고르고 이유를 한 줄로 말한다.
   - Lite: 기존 계약 안에서 끝나고, 바뀌는 파일이 대략 5개 이하이며, 데이터 구조가 바뀌지 않는다.
   - Full: 새 API·데이터 모델·화면 흐름이 생기거나, 여러 영역에 걸친다.
3. **폴더 생성** — `specs/NNN-<영문-kebab-이름>/`을 만든다. 번호는 `docs/product.md` 기능 목록에 이미 있는 ID를 쓰고, 없으면 기능 목록과 `specs/`를 통틀어 가장 큰 번호 + 1을 쓴다.
4. **작성** — `specs/_templates/<full|lite>/spec.md`를 복사해 채운다.
   - 범위의 포함·제외를 분명히 하고, 정상·입력 오류·실패와 복구 AC를 모두 쓴다.
   - AC의 Then은 화면이나 데이터에서 관찰 가능한 결과로 쓴다.
   - 요청에 없는 정책(제한값, 문구, 권한 등)은 지어내지 말고 `[확인 필요: …]`로 남긴다.
   - 기술 선택·파일 구조는 쓰지 않는다(Full의 경우 plan.md의 몫).
5. **제품 문서 갱신** — `docs/product.md`의 기능 목록에 행을 추가하거나 링크를 채운다.

## 끝나면 보고

- 만든 파일 경로와 선택한 트랙
- AC 목록 (ID와 한 줄 요약)
- `[확인 필요]` 항목 수와 그중 구현을 막는 것
- 다음 단계: `[확인 필요]`가 있으면 `/sdd-clarify`, 없으면 Full은 `/sdd-plan`, Lite는 `/sdd-implement`

소스 코드는 수정하지 않는다.
