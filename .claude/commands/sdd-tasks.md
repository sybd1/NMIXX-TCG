대상: $ARGUMENTS (비어 있으면 `specs/`에서 상태가 Verified가 아닌 폴더 중 번호가 가장 큰 것)

## 절차

1. `spec.md`, `plan.md`를 읽는다.
2. `specs/_templates/full/tasks.md`를 복사해 작업을 채운다.
   - 순서: 계약·기반 → AC 테스트 작성(실패 확인) → 구현 → 통합 검증
   - 각 작업에 파일, 연결 AC, 완료 기준을 적는다. 완료 기준은 실행할 수 있는 명령이나 관찰 가능한 결과로 쓴다.
   - 다른 작업과 파일이 겹치지 않으면 `[P]`를 붙인다.
   - 작업 하나는 한 번에 검토할 수 있는 크기로 나눈다.
3. 검증 기록 표에 spec의 모든 AC 행을 `미실행`으로 만든다. 프로젝트 검사 명령은 `CLAUDE.md`에서 가져온다.
4. **정합성 점검** — 아래를 확인하고 결과를 보고한다. 고칠 수 있는 것은 고친다.
   - spec의 모든 AC가 plan 6절과 tasks에 있는가
   - spec에 없는 동작이 plan·tasks에 들어가 있지 않은가
   - plan의 계약(필드명·타입·상태 코드·오류 코드)과 spec의 규칙·문구가 일치하는가
   - 테스트 작업이 구현 작업보다 앞에 있는가
5. 문제가 없으면 spec·plan·tasks의 상태를 `Ready`로 바꾼다.

## 끝나면 보고

- 작업 수, 병렬 가능한 작업, 막힌 작업
- 정합성 점검 결과 (고친 것 / 사용자 결정이 필요한 것)
- 다음 단계: `/sdd-implement` (첫 작업 ID)

소스 코드는 수정하지 않는다.
