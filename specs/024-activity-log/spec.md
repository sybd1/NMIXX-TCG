## 1. 문제와 목표

지금은 이용자가 무엇을 했는지 남는 기록이 거의 없다. 남는 것은 다음뿐이다.
- `nmixx_tcg_users`의 `createdAt`·`lastLoginAt`(덮어쓰기)·`lastSavedAt`
- 랭킹 문서의 `updatedAt`·`fullCollectionAt`
- 전광판, 교환소 데이터

Vercel Analytics(Hobby)는 최근 31일 집계만 보여 주고, 이용자 개인 단위로는 볼 수 없다. 그래서 문제가 생겨도 "누가 언제 무엇을 했는지" 확인할 수 없다.

이 기능이 끝나면 로그인 이용자의 주요 행동이 Firestore에 이벤트로 남는다. 운영자는 이용자 ID로 그 이용자의 행동 기록을 시간순으로 조회할 수 있다.

## 2. 범위

- 포함
  - 이벤트 컬렉션 `nmixx_tcg_events`와 그 보안 규칙
  - 기록할 이벤트: 접속(세션 시작), 로그인, 로그아웃, 팩 개봉(팩 종류, 팩 수, 쓴 코인, 나온 등급 수), 세트 보상 수령, 업적 보상 수령, XR 카드 획득, 쿠폰 사용, 우편 수령
  - 보관 기간이 지난 이벤트 삭제(REQ-04)
  - 회원 탈퇴 시 그 이용자의 이벤트 삭제(REQ-05, 기능 014와 연결)
  - 앱 안 개인정보 고지 문구(REQ-06)
- 제외
  - 교환 등록·완료 — 교환소는 메뉴에서 숨겨져 있고, 기능 022 이후 쓰기가 막혀 있다(기능 022 REQ-04).
  - 회원 탈퇴 이벤트 — 탈퇴하면 이벤트를 지우므로 남길 수 없다(REQ-05).
  - 관리용 조회 화면 — 조회는 Firebase 콘솔에서 한다(Q-F). 필요하면 별도 기능으로 한다.
  - 일일 보너스·더스트·이스터에그 — 숨김 기능이거나 보상이 작다. 필요하면 나중에 추가한다.
  - 새 의존성, 서버 측 집계
- 선행 조건
  - 기능 022(규칙 운영 배포 완료). 이벤트 쓰기도 "Firebase 인증을 받은 문서 주인만" 원칙을 따른다.
  - 카카오 사용자는 기능 023이 운영에 나갈 때까지 Firebase 인증이 없다. 그래서 그동안 카카오 사용자의 이벤트는 기록되지 않는다(REQ-01 AC-03). 요청 원문의 "DEC-026(규칙 강화는 카카오 연동 뒤)"은 DEC-028로 대체되어 규칙은 이미 운영에 있다.

## 3. 사용자 흐름

이용자 화면은 고지 문구 외에는 바뀌지 않는다.

1. 로그인 이용자가 사이트를 열거나 로그인하면 접속 이벤트가 남는다.
2. 팩을 열거나 보상을 받으면 해당 이벤트가 남는다.
3. 기록에 실패해도(네트워크, 권한) 게임 진행은 그대로다.
4. 운영자는 Firebase 콘솔에서 `nmixx_tcg_events`를 이용자 ID로 걸러 시간순으로 본다.
5. 회원 탈퇴하면 그 이용자의 이벤트가 함께 지워진다.

## 4. 요구사항과 인수 조건(AC)

### REQ-01: 로그인 이용자의 행동만, 본인 이름으로 기록한다

이벤트 하나에는 다음 항목이 들어간다.
- 이용자 ID(계정 ID: `goog_…`·`kakao_…`)
- 이벤트 종류
- 서버 기준 발생 시각
- KST 날짜(YYYY-MM-DD)
- 세션 구분값
- 종류별 작은 부가 정보

게스트는 기록하지 않는다(Q-A 잠정, DEC-009 유지).

- **AC-01** 정상: 팩 개봉 기록
  - Given 구글 로그인 이용자 A
  - When 팩 1개를 연다
  - Then `nmixx_tcg_events`에 `uid: goog_A`, 종류 `pack_open`, 팩 종류·팩 수·쓴 코인·등급별 장수가 담긴 문서가 1개 생긴다. 발생 시각은 서버 시각, KST 날짜는 KST 기준 오늘이다
- **AC-02** 정상: 접속·로그인·로그아웃 기록
  - Given 로그인 이용자 A
  - When 사이트를 열고, 로그아웃했다가 다시 로그인한다
  - Then 다음 문서가 남는다: 사이트를 열 때 `session_start` 1개, 로그아웃 시 `logout` 1개, 로그인 시 `login`(제공자 포함)과 `session_start`
- **AC-03** 권한 오류: 남의 이름·비로그인 기록 거부
  - Given 이용자 A, 다른 이용자 B
  - When A가 `uid: goog_B`로 이벤트를 쓰거나, 로그인하지 않은 요청(Firebase 인증이 없는 카카오 세션 포함)이 이벤트를 쓴다
  - Then 거부되고 이벤트가 생기지 않는다. 게임 화면에는 오류가 보이지 않는다
- **AC-04** 입력 오류: 정해지지 않은 형식 거부
  - Given 이용자 A
  - When 정해진 종류가 아닌 이벤트, 정해진 항목 밖의 필드, 서버 시각이 아닌 발생 시각, 지나치게 큰 부가 정보를 쓰려 한다
  - Then 거부된다
- **AC-05** 실패·복구: 기록 실패가 게임을 막지 않는다
  - Given 네트워크가 끊겼거나 기록이 거부되는 상황
  - When 팩을 열고 보상을 받는다
  - Then 게임 진행(코인·도감·저장)은 기록이 없을 때와 같고, 화면에 오류가 보이지 않는다
- **AC-06** 경계: 같은 보상을 두 번 눌러도 한 번만 기록
  - Given 이미 받은 세트 보상·업적·우편·쿠폰
  - When 다시 받으려 한다(받기 처리 자체가 무시되는 경우)
  - Then 이벤트가 새로 생기지 않는다

### REQ-02: 기록할 이벤트 종류

| 종류 | 언제 | 부가 정보 |
|---|---|---|
| `session_start` | 로그인 상태로 앱을 열거나 로그인 직후 상태를 불러왔을 때 | 없음 |
| `login` | 구글·카카오 로그인 성공 | 제공자 |
| `logout` | 로그아웃 직전 | 없음 |
| `pack_open` | 팩 개봉 확정 | 팩 ID, 팩 수, 쓴 코인, 등급별 장수 |
| `set_reward` | 세트 보상 수령 | 세트 ID, 받은 코인 |
| `achievement` | 업적 보상 수령 | 업적 ID, 받은 코인 |
| `xr_card` | XR 카드 획득 | 카드 ID |
| `coupon` | 쿠폰 사용 성공 | 쿠폰 코드, 받은 코인 |
| `mail` | 우편 수령 | 우편 ID, 받은 코인 |

- **AC-07** 정상: 보상 이벤트
  - Given 로그인 이용자 A
  - When 세트 보상, 업적 보상, XR 카드, 쿠폰, 우편을 각각 처음 받는다
  - Then 위 표의 종류와 부가 정보를 가진 문서가 각각 1개씩 생긴다

### REQ-03: 이용자 단위 조회

- **AC-08** 정상: 운영자 조회
  - Given A의 이벤트가 여러 개 있다
  - When 운영자가 Firebase 콘솔에서 `nmixx_tcg_events`를 `uid == goog_A`로 거르고 발생 시각으로 정렬한다
  - Then A의 행동이 시간순으로 보인다
- **AC-09** 권한 오류: 다른 이용자는 볼 수 없다
  - Given A의 이벤트
  - When B 또는 로그인하지 않은 요청이 A의 이벤트를 읽거나 목록을 조회한다
  - Then 거부된다(A 본인 조회 허용 여부는 REQ-04·05 처리에 필요한 범위로 plan에서 정함)

### REQ-04: 보관 기간

이벤트는 **90일** 동안 보관한 뒤 삭제한다(Q-C 잠정). Firestore TTL은 결제 활성화가 필요하므로 쓰지 않는다. 대신 이용자가 접속할 때(세션 시작) 그 이용자 본인의 90일 지난 이벤트를 한 번에 최대 100개까지 지운다. 오래 접속하지 않은 이용자의 기록은 다음 접속까지 남는다. 확인한 사실: Firestore TTL 정책은 공식 문서상 "TTL 삭제는 무료 사용량이 없고 결제 활성화가 필요"하며, 만료 후 보통 24시간 안에 지운다.

- **AC-10** 정상: 기간이 지난 이벤트 삭제
  - Given A의 이벤트 중 보관 기간이 지난 것이 있다
  - When A가 접속한다(세션 시작)
  - Then 발생 시각이 90일보다 오래된 A의 이벤트가 사라지고(최대 100개), 90일 안의 이벤트와 다른 이용자의 이벤트는 남는다
- **AC-11** 실패·복구: 삭제 실패
  - Given 삭제가 실패한다(네트워크·권한)
  - When 게임을 계속한다
  - Then 게임 진행과 화면은 영향을 받지 않고, 다음 기회에 다시 시도된다

### REQ-05: 회원 탈퇴 시 이벤트 삭제

- **AC-12** 정상: 탈퇴하면 이벤트도 지워진다 (Q-D 잠정: 지운다)
  - Given 이벤트가 있는 이용자 A
  - When 회원 탈퇴한다(기능 014)
  - Then `uid == goog_A`인 이벤트가 모두 사라진다. 다른 이용자의 이벤트는 그대로다
- **AC-13** 실패·복구: 이벤트 삭제 실패
  - Given 이벤트 삭제가 실패한다
  - When 탈퇴를 진행한다
  - Then 탈퇴를 멈추고 기존 문구 `탈퇴 처리 중 오류가 발생했습니다. 잠시 후 다시 시도해 주세요.`를 보여 준다. 사용자 문서·랭킹 문서·인증 계정은 지우지 않은 상태로 남는다. 탈퇴 후에는 본인만 지울 수 있어 남은 이벤트를 정리할 방법이 없으므로, 이벤트를 먼저 지운다(Q-D 잠정)

### REQ-06: 개인정보 고지

- **AC-14** 정상: 고지 문구
  - Given 이용자
  - When 정보 탭을 열거나 로그인 창을 연다
  - Then 정보 탭에 `로그인 이용자의 게임 이용 기록(접속, 로그인·로그아웃, 팩 개봉, 보상 수령)을 부정 이용 확인과 서비스 개선을 위해 90일 동안 보관합니다. 이메일·닉네임은 기록하지 않으며, 회원 탈퇴 시 함께 삭제됩니다.`가, 로그인 창에 `로그인하면 게임 이용 기록이 90일 동안 보관됩니다. 자세한 내용은 정보 탭을 확인해 주세요.`가 보인다. 별도 동의 절차는 두지 않는다(Q-B 잠정)

## 5. 화면 상태

화면 흐름은 바뀌지 않는다. 고지 문구 한 줄이 추가된다(REQ-06, Q-B).

- 주요 문구: 정보 탭 `로그인 이용자의 게임 이용 기록(접속, 로그인·로그아웃, 팩 개봉, 보상 수령)을 부정 이용 확인과 서비스 개선을 위해 90일 동안 보관합니다. 이메일·닉네임은 기록하지 않으며, 회원 탈퇴 시 함께 삭제됩니다.` / 로그인 창 `로그인하면 게임 이용 기록이 90일 동안 보관됩니다. 자세한 내용은 정보 탭을 확인해 주세요.`
- 접근성·반응형: 기존 화면과 같음

## 6. 품질 요구

- 비용(공식 문서 확인, firebase.google.com/docs/firestore/quotas)
  - 무료 한도: 저장 1 GiB, 읽기 50,000/일, 쓰기 20,000/일, 삭제 20,000/일
  - 최근 31일 방문자는 약 18명이고, 세션당 이벤트는 수십 개 이하로 예상한다. 무료 한도 안이다.
  - 이벤트마다 즉시 쓴다(Q-E 잠정). 양이 적어 모아 쓰기의 이득이 작고, 탭을 닫을 때 모아 둔 기록을 잃는 위험이 없다.
- 개인정보
  - 이벤트에는 이메일·닉네임을 넣지 않는다. 이용자 ID와 행동만 남긴다.
  - 쿠폰 코드는 이용자 개인정보가 아니므로 넣는다.
- 성능: 이벤트 기록은 게임 진행을 기다리게 하지 않는다(AC-05).
- 운영 데이터 보호
  - `npm run dev`도 운영 Firestore에 연결된다. 그래서 개발 중(localhost)에는 이벤트를 쓰지 않는다. 기존 클라우드 저장이 localhost에서 쓰지 않는 규칙(DEC-017)과 같다.
  - 검증은 에뮬레이터 규칙 테스트와 단위 테스트로 한다.
- KST 날짜는 `Date.now() + 9h` 규칙을 따른다.

## 7. 미결 질문

사용자가 자리를 비운 상태에서 "끝까지 진행" 지시를 받아(2026-11-26), 아래 여섯 질문은 묻지 않고 **잠정 결정**했다. 기준은 되돌리기 쉽고 위험이 작은 선택이다. 모두 DEC-031에 기록했고 **사용자 확인이 필요하다**. 바꾸려면 `/sdd-change`로 한다.

- Q-A 잠정: 게스트는 기록하지 않는다(DEC-009 유지).
- Q-B 잠정: 정보 탭에 고지 문구, 로그인 창에 짧은 안내를 둔다. 별도 동의 절차는 두지 않는다. 문구는 5절과 같다.
- Q-C 잠정: 90일 보관. TTL(결제 필요) 대신 이용자 접속 시 본인의 오래된 이벤트를 최대 100개 지운다.
- Q-D 잠정: 탈퇴 시 이벤트를 먼저 지우고, 실패하면 탈퇴를 멈춘다.
- Q-E 잠정: 이벤트마다 즉시 쓴다.
- Q-F 잠정: 조회는 Firebase 콘솔로 한다. 관리용 화면은 범위 밖이다.
