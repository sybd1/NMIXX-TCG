# Spec 008: 게임 데이터 저장과 기기 간 동기화

- 최종 수정일: 2026-11-10

- 디자인 자료: 없음 — 화면 요소 없음(백그라운드 동작)

## 1. 문제와 목표

로그인한 사용자는 PC에서 연 카드를 휴대폰에서도 보고 싶고, 새로고침이나 로그아웃으로 진행이 사라지면 안 된다. 이 기능 이후 로그인 계정의 코인·컬렉션·천장·보상 수령 기록은 상태가 바뀔 때마다 브라우저와 클라우드에 저장되고, 같은 계정으로 열린 다른 기기에도 곧바로 반영된다. 게스트는 저장하지 않는다(DEC-009).

## 2. 범위

- 포함: 로그인 계정 상태의 localStorage 저장, Firestore 저장, 로그인 시 클라우드 복원, 다른 기기 변경 실시간 수신, 로그아웃 전 강제 저장, 저장 시 랭킹 문서 갱신 호출
- 제외: 충돌 병합(마지막 쓰기 우선, DEC-011) / 오프라인 쓰기 큐 / 게스트 진행 이관(DEC-009) / 랭킹 정렬 규칙 — 기능 010
- 선행 조건: 기능 007(로그인)

## 3. 사용자 흐름

1. 사용자가 구글 또는 카카오로 로그인한다.
2. 앱이 클라우드 저장본을 불러와 화면의 코인·도감을 그 값으로 바꾼다. 저장본이 없으면 초기 상태(100만 N, 운영자는 DEC-012)를 만들어 올린다.
3. 팩 개봉·보상 수령 등으로 상태가 바뀌면 별도 조작 없이 저장된다.
4. 다른 기기에서 같은 계정으로 상태가 바뀌면 이 기기의 화면도 바뀐다.
5. 로그아웃하면 저장을 한 번 더 한 뒤 게스트 초기 상태로 돌아간다. 다시 로그인하면 진행이 그대로 있다.

## 4. 요구사항과 인수 조건(AC)

### REQ-01: 로그인 계정 상태 저장

저장 대상 필드는 plan 3절 `CloudGameData`. 로컬에는 `GameState` 전체를 `nmixx_tcg_user_<uid>` 키로 저장한다.

- **AC-01** 정상: 상태가 바뀌면 로컬과 클라우드에 저장된다
  - Given 로그인 계정, 코인 1,000,000
  - When 1팩(3,800 N)을 연다
  - Then `localStorage['nmixx_tcg_user_<uid>'].coins`가 996,200이 된다
  - 그리고 Firestore `nmixx_tcg_users/<uid>`의 `coins`가 996,200, `totalPacksOpened`가 1 늘고 `lastSavedAt`이 갱신된다
- **AC-02** 경계: 게스트 상태는 어디에도 저장되지 않는다
  - Given 게스트로 1팩을 연 상태
  - When 페이지를 새로고침한다
  - Then 코인이 1,000,000, 도감이 0장으로 돌아간다
  - 그리고 `localStorage`에 `nmixx_tcg_guest` 키가 없다
- **AC-03** 중복 쓰기 방지: 바뀐 값이 없으면 Firestore에 다시 쓰지 않는다
  - Given 직전 저장 이후 저장 대상 값이 같은 상태
  - When 상태 객체만 새로 만들어진다(예: `isFirstVisit` 변경)
  - Then Firestore 쓰기 요청이 발생하지 않는다

### REQ-02: 로그인 시 복원

- **AC-04** 정상: 다른 기기의 진행을 불러온다
  - Given 기기 A에서 카드 50종, 코인 800,000으로 저장된 계정
  - When 기기 B(저장본 없음)에서 같은 계정으로 로그인한다
  - Then 기기 B의 도감이 50종, 코인이 800,000으로 보인다
- **AC-05** 최초 로그인: 새 계정은 초기 상태로 시작하고, 이후 로그인에서 초기화되지 않는다
  - Given Firestore에 문서가 없는 새 계정
  - When 로그인한다
  - Then 화면이 코인 1,000,000, 도감 0장으로 시작한다
  - 그리고 첫 상태 변경(예: 1팩 개봉) 뒤 Firestore 문서에 `coins`·`collection`이 생기고, 다시 로그인해도 그 값이 유지된다
  - (로그인 함수가 프로필 필드를 먼저 쓰므로 "문서 없음" 분기는 거의 타지 않는다. plan 7절)
- **AC-06** 실패·복구: 복원 중에는 로컬 빈 상태가 클라우드를 덮지 않는다
  - Given 클라우드에 진행이 있는 계정, 이 기기는 게스트 초기 상태
  - When 로그인 직후 클라우드 응답이 오기 전에 상태가 바뀐다
  - Then 클라우드 문서의 컬렉션·코인이 초기값으로 바뀌지 않는다

### REQ-03: 기기 간 실시간 반영

- **AC-07** 정상: 다른 기기의 변경이 즉시 반영된다
  - Given 기기 A와 B에 같은 계정으로 로그인한 상태
  - When A에서 팩을 연다
  - Then B를 새로고침하지 않아도 B의 코인·도감이 A와 같아진다
- **AC-08** 루프 방지: 받은 변경을 다시 올리지 않는다
  - Given AC-07 상황
  - When B가 A의 변경을 받는다
  - Then B는 그 변경 때문에 Firestore에 쓰지 않는다(쓰기 요청 0회)

### REQ-04: 로그아웃·계정 전환

- **AC-09** 정상: 로그아웃 전에 마지막 상태를 저장한다
  - Given 카카오 계정으로 팩을 연 직후
  - When 곧바로 로그아웃하고 같은 계정으로 다시 로그인한다
  - Then 로그아웃 직전의 코인·도감이 그대로 있다
- **AC-10** 격리: 로그아웃 후 게스트 상태가 계정 데이터를 덮지 않는다
  - Given 로그인 계정에서 로그아웃한 직후
  - When 게스트 상태(100만 N, 0장)로 화면이 바뀐다
  - Then 그 계정의 Firestore 문서와 `nmixx_tcg_user_<uid>`는 바뀌지 않는다

### REQ-05: 로컬 개발 환경

- **AC-11** 로컬에서는 클라우드에 쓰지 않는다 (DEC-017)
  - Given `localhost`에서 로그인한 상태
  - When 팩을 연다
  - Then 도감은 전종 보유로 보이고, Firestore 유저·랭킹 문서는 바뀌지 않는다

## 5. 화면 상태

화면 요소 없음. 저장 실패는 사용자에게 알리지 않고 `console.warn`만 남긴다(알려진 한계, 7절).

## 6. 품질 요구

- 저장 대상 값은 Firestore 문서 하나(1MiB 제한)에 들어가야 한다. 현재 컬렉션 맵은 최대 521키라 여유 있다.
- 다른 사용자의 문서를 읽거나 쓰지 않는다. [확인 필요: 콘솔에 배포된 Firestore 규칙이 저장소 `firestore.rules`와 같은지 — 저장소 규칙은 인증된 누구나 모든 유저 문서를 쓸 수 있다 — 구현 막음: 아니오]

## 7. 미결 질문

- [확인 필요: 카카오 로그인은 Firebase Auth를 거치지 않아(DEC-008) `request.auth`가 null이다. 저장소 규칙대로면 카카오 사용자의 Firestore 쓰기가 거부되어야 하는데 실제 운영에서 저장이 되는지 — 영향: AC-01, AC-04, AC-09 — 구현 막음: 아니오]
- 알려진 한계: 중복 쓰기 방지 해시(plan 3절)에 `dust`와 카드별 보유 수가 들어가지 않아, 더스트만 바뀌거나 이미 가진 카드의 수량만 바뀐 경우 클라우드 저장이 생략된다. 코인이 같이 바뀌는 팩 개봉은 영향 없다. 더스트(기능 015)를 다시 열기 전에 고친다.
- 알려진 한계: `coinsSpentTotal`, `packHistory`, `lastDailyBonus`, `cardEasterEggClaims`는 클라우드에 저장하지 않아 기기마다 다르다.
