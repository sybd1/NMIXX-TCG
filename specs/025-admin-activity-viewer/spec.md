## 1. 문제와 목표

기능 024로 로그인 이용자의 행동이 `nmixx_tcg_events`에 쌓이지만, 지금은 Firebase 콘솔에서 문서를 한 건씩 넘겨 봐야 한다(024 Q-F). 날짜별 이용량이나 한 회원의 흐름을 한눈에 보기 어렵다.

이 기능이 끝나면 운영자는 게임 사이트의 숨김 주소에서 기간을 고르고, 날짜별 요약·회원 목록·회원별 시간순 기록을 볼 수 있다. 일반 이용자는 이 화면과 다른 사람의 기록을 볼 수 없다.

## 2. 범위

- 포함
  - 숨김 주소 `/#admin`의 읽기 전용 조회 화면
  - 운영자 계정 1개(구글)에만 모든 이용자의 이벤트 읽기를 허용하는 보안 규칙
  - 기간 선택(오늘·7일·30일), 종류 필터, 날짜별 요약, 회원 목록, 회원 상세(시간순)
  - 회원 표시 이름은 공개 랭킹 문서의 닉네임을 쓴다(없으면 계정 ID)
- 제외
  - 이벤트 수정·삭제, 회원 데이터(`nmixx_tcg_users`) 조회·수정 — 읽기 전용 화면이다(DEC-023)
  - 운영자 계정 추가·변경 화면 — 규칙과 설정 파일을 고쳐 배포한다
  - 메뉴·탭에 들어가는 링크 — 주소를 아는 운영자만 쓴다
  - 내보내기(CSV), 그래프, 실시간 갱신 — 필요하면 나중에 한다
  - 새 의존성
- 선행 조건: 기능 024(이벤트 기록, 운영 배포 완료), 기능 022(규칙)

## 3. 사용자 흐름

1. 운영자가 게임에서 운영자 구글 계정으로 로그인해 둔다.
2. `https://nmixx-tcg.vercel.app/#admin`을 연다. 게임 화면 대신 조회 화면이 열린다.
3. 기본 기간은 7일이다. 불러오는 동안 "불러오는 중…"이 보인다.
4. 날짜별 요약과 회원 목록(최근 활동 순)이 보인다. 회원을 누르면 그 회원의 기록이 시간순으로 보인다.
5. 운영자가 아니거나 로그인하지 않았으면 안내 문구만 보이고 기록은 불러오지 않는다.
6. 불러오기에 실패하면 오류 문구와 "다시 시도" 버튼이 보인다.

## 4. 요구사항과 인수 조건(AC)

### REQ-01: 운영자만 모든 이벤트를 읽는다

운영자는 정해진 구글 계정 1개다(DEC-032). 운영자도 이벤트를 만들거나 지우거나 고칠 수 없다(본인 이벤트 제외, 기능 024 그대로).

- **AC-01** 정상: 운영자 조회
  - Given 운영자 구글 계정으로 로그인, 이용자 A·B의 이벤트가 있다
  - When 기간 조건으로 이벤트 목록을 읽는다
  - Then A·B의 이벤트가 모두 읽힌다
- **AC-02** 권한 오류: 운영자가 아닌 계정
  - Given 일반 구글 이용자 A, 카카오 이용자 K, 비로그인
  - When `uid` 조건 없이 이벤트 목록을 읽거나 B의 이벤트를 읽는다
  - Then 거부된다(기능 024 AC-09 유지). 본인 이벤트 읽기는 그대로 허용된다
- **AC-03** 권한 오류: 운영자도 남의 이벤트를 바꿀 수 없다
  - Given 운영자 로그인
  - When B의 이벤트를 지우거나 고치거나 B 이름으로 만든다
  - Then 거부되고 데이터가 그대로다
- **AC-04** 화면 차단: 운영자가 아니면 기록을 불러오지 않는다
  - Given 비로그인 또는 운영자가 아닌 계정으로 `/#admin`을 연다
  - When 화면이 열린다
  - Then `운영자 계정으로 로그인한 뒤 다시 열어 주세요.`만 보이고, 이벤트 조회 요청을 보내지 않는다

### REQ-02: 기간·종류로 모아 본다

- **AC-05** 정상: 날짜별 요약
  - Given 기간 안에 이벤트가 있다
  - When 기간을 고른다(오늘·7일·30일, 기본 7일)
  - Then KST 날짜별로 접속 회원 수(서로 다른 uid), 로그인 수, 팩 개봉 수(팩 수 합), 보상 수령 수(세트·업적·XR·쿠폰·우편)가 최신 날짜부터 보인다
- **AC-06** 정상: 회원 목록
  - Then 기간 안에 활동한 회원이 마지막 활동 시각 최신순으로 보인다. 각 행: 닉네임(랭킹 문서, 없으면 계정 ID), 계정 종류(구글·카카오), 이벤트 수, 팩 개봉 수, 마지막 활동 시각(KST)
- **AC-07** 정상: 회원 상세
  - When 회원 행을 누른다
  - Then 그 회원의 기간 안 이벤트가 최신순으로 보인다. 각 줄: KST 시각, 종류 이름(한국어), 부가 정보 요약(예: `op01 1팩 · 3,800코인 · SSR 1, R 4`)
- **AC-08** 정상: 종류 필터
  - When 종류를 하나 고른다(전체 포함)
  - Then 요약·목록·상세가 그 종류의 이벤트만으로 다시 계산된다(새 조회 없이)
- **AC-09** 빈 상태
  - Given 기간 안에 이벤트가 없다
  - Then `이 기간에 기록이 없습니다.`가 보인다
- **AC-10** 경계: 읽기 상한
  - Given 기간 안 이벤트가 2,000건을 넘는다
  - Then 최신 2,000건만 불러오고 `최근 2,000건만 표시합니다. 기간을 줄여 주세요.`가 보인다

### REQ-03: 실패와 복구

- **AC-11** 실패·복구: 불러오기 실패
  - Given 네트워크 오류나 권한 거부
  - When 불러오기가 실패한다
  - Then `기록을 불러오지 못했습니다.`와 "다시 시도" 버튼이 보이고, 누르면 같은 기간으로 다시 불러온다. 게임 데이터는 바뀌지 않는다

## 5. 화면 상태

| 상태 | 진입 조건 | 보이는 것 | 가능한 행동 |
|---|---|---|---|
| 확인 중 | 인증 복원 전 | `확인 중…` | 없음 |
| 권한 없음 | 비로그인·운영자 아님 | AC-04 문구, `게임으로 돌아가기` 링크 | 게임으로 이동 |
| 불러오는 중 | 기간 변경·다시 시도 | `불러오는 중…`, 기간 버튼 비활성 | 없음 |
| 성공 | 조회 완료 | 요약 표, 회원 목록, 선택 시 상세 | 기간·종류 변경, 회원 선택 |
| 빈 상태 | 결과 0건 | AC-09 문구 | 기간 변경 |
| 오류 | 조회 실패 | AC-11 문구, 다시 시도 | 다시 시도 |

- 주요 문구: 제목 `행동 로그 (운영자)`, 기간 `오늘`·`7일`·`30일`, 종류 이름 `접속`·`로그인`·`로그아웃`·`팩 개봉`·`세트 보상`·`업적 보상`·`XR 카드`·`쿠폰`·`우편`
- 반응형: 휴대폰 폭(375px)에서 표가 가로로 스크롤된다

## 6. 품질 요구

- 권한: 운영자 판정은 보안 규칙이 한다. 화면의 운영자 확인은 안내용이다(규칙 테스트로 확인).
- 비용: 한 번 불러올 때 이벤트 최대 2,000건 + 회원 수만큼 랭킹 문서 읽기. 무료 한도(읽기 50,000/일) 안에서 하루 여러 번 볼 수 있다.
- 개인정보: 이메일은 보이지 않는다(이벤트·랭킹 문서에 없음). 화면은 메뉴에 노출하지 않는다.
- 게임 영향: `/#admin`이 아닐 때 게임 번들과 동작은 바뀌지 않는다. 조회 화면 코드는 따로 불러온다.

## 7. 미결 질문
