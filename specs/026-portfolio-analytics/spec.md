## 1. 문제와 목표

운영자는 이 게임을 실제 포트폴리오에 쓰려고 한다. 지금 쌓이는 행동 로그(기능 024: 접속·로그인·로그아웃·팩 개봉·보상 수령)는 "누가 무엇을 했나"만 보여 준다. 그래서 포트폴리오에 넣을 만한 지표가 나오지 않는다(2026-11-27 사용자: "현재 로그는 딱히 포트폴리오에 사용할 것은 없는 것 같아").

이 기능 이후에는 두 종류의 지표를 실제 운영 데이터로 계산해 보여 줄 수 있다(사용자 선택: "이용자 분석 (데이터·기획)", "성능·오류 (개발자)").

- 이용자 분석: 재방문율, 첫 팩까지 걸린 시간, 화면 이동과 이탈 지점, 세션 길이, 도감 수집 속도, 실제 등급 비율과 설정 확률 비교
- 성능·오류: 첫 화면 로딩 지표, 3D 팩 화면 로딩 시간과 프레임, 이용자 화면에서 난 오류의 종류와 횟수

## 2. 범위

- 포함
  - 새 행동 기록: 화면(탭) 이동, 세션 종료와 길이, 팩 개봉 시점의 도감 수집 수(REQ-01~03)
  - 성능 기록: 첫 화면 로딩 지표, 3D 팩 화면 로딩 시간·프레임, 2D 대체 여부(REQ-05)
  - 오류 기록: 이용자 화면에서 잡히지 않은 오류의 종류·횟수(REQ-06)
  - 위 기록과 기존 024 기록으로 지표를 계산하고 운영자가 볼 수 있게 하기(REQ-04, REQ-07)
  - 개인정보 고지 문구 갱신(REQ-08)
- 제외
  - 기존 024 이벤트의 모양·권한 변경 — 이미 운영 중이고 탈퇴 삭제 흐름이 걸려 있다. 새 기록은 기존 기록에 더한다
  - 외부 분석 도구(GA4 등)로 옮기기 — 024에서 이용자 단위 조회가 어려워 제외했다(DEC-031)
  - CSV 내보내기, 누구나 보는 공개 지표 페이지 — 사용자가 운영자 화면만 골랐다(Q1)
  - A/B 테스트, 푸시 알림, 마케팅 유입 경로 분석 — 요청에 없다
  - 서버 쪽 성능(카카오 토큰 함수) 측정 — 요청은 이용자 화면 기준이다
- 선행 조건: 기능 024(행동 로그, 운영 배포), 기능 025(운영자 화면 `/#admin`), 기능 022(규칙)

## 3. 사용자 흐름

이용자(기록 대상)
1. 사이트를 연다. 첫 화면 로딩 지표가 측정된다.
2. 탭을 옮기고, 팩을 열고, 보상을 받는다. 각 행동이 기록된다. 이용자가 기다리는 일은 없다.
3. 3D 팩 화면이 열리면 로딩 시간과 프레임이 측정된다. WebGL이 없어 2D로 바뀌면 그 사실이 기록된다.
4. 화면에서 오류가 나면 종류가 기록된다. 게임은 기존처럼 동작한다.
5. 탭을 닫거나 다른 앱으로 가면 세션 종료가 기록된다. 기록이 실패해도 이용자에게는 보이지 않는다.

운영자(지표 확인)
1. 게임에 운영자 구글 계정으로 로그인한 뒤 `/#admin`을 열고 `지표` 탭을 누른다.
2. 기간을 고르면 지표와 근거 수치(표본 수)가 보인다.
3. 표본이 부족한 지표는 숫자 대신 부족하다는 표시가 보인다.
4. 불러오기가 실패하면 오류 문구와 다시 시도가 보인다.

## 4. 요구사항과 인수 조건(AC)

공통 규칙
- 기록 대상은 **로그인하지 않은 방문자를 포함한 모든 방문자**다(Q2 답 2026-11-27: "비로그인도 기록", DEC-034).
  - 비로그인 방문자는 브라우저마다 이름 없는 무작위 번호(방문자 ID)로 구분한다. 이 번호로는 누구인지 알 수 없다. 같은 브라우저로 다시 오면 같은 번호다. 브라우저 저장소를 지우거나 다른 기기로 오면 새 방문자로 센다.
  - 로그인 이용자의 기록에는 계정 ID를 붙인다(024와 같음). [확인 필요: 비로그인으로 시작해 로그인한 경우 방문자 ID와 계정 ID를 이어 붙일지 — 영향: 첫 팩까지 시간·재방문율의 정확도, 탈퇴 삭제 범위 — 구현 막음: 아니오(기본은 로그인 기록에 방문자 ID를 함께 남김)]
  - 게스트 게임 데이터를 저장하지 않는다는 DEC-009는 바뀌지 않는다. 방문자 ID는 분석 기록에만 쓰고 게임 진행(코인·카드)은 저장하지 않는다.
- 이메일·닉네임은 넣지 않는다. 오류 기록에도 이용자 입력값(쿠폰 코드 입력 중인 값 등)을 넣지 않는다.
- 개발 중(localhost)에는 기록하지 않는다(DEC-017과 같은 이유).
- 기록은 게임을 기다리게 하지 않고, 실패해도 게임을 막지 않는다(024 AC-05와 같음).

### REQ-01: 화면(탭) 이동 기록

이용자가 어느 화면에 들어갔는지 남겨 이동 경로와 마지막으로 본 화면(이탈 지점)을 계산한다. 대상 화면은 하단·상단 탭의 화면(홈, 도감, 업적, 랭킹, 정보)과 팩 개봉 화면이다. [확인 필요: 우편함·프로필·로그인 창 같은 팝업도 포함할지 — 영향: AC-01 — 구현 막음: 아니오(기본은 탭 화면만)]

- **AC-01** 정상: 탭 이동 기록
  - Given 방문자(로그인 여부 무관)가 홈 화면에 있다
  - When 도감 탭을 누른다
  - Then 화면 이동 기록 1건이 남는다: 들어간 화면 `도감`, 직전 화면 `홈`, 방문자 ID(로그인이면 계정 ID도), 세션 ID, 시각
- **AC-02** 경계: 같은 화면 반복
  - Given 이용자가 도감 화면에 있다
  - When 도감 탭을 다시 누른다
  - Then 새 기록이 남지 않는다
- **AC-03** 실패·복구: 기록 실패
  - Given 기록 쓰기가 실패한다(네트워크·권한)
  - When 탭을 옮긴다
  - Then 화면은 바로 바뀌고 오류 문구가 보이지 않는다. 실패한 기록은 다시 보내지 않는다 [확인 필요: 실패 기록을 다시 보낼지 — 영향: AC-03 — 구현 막음: 아니오(기본은 버림, 024와 같음)]

### REQ-02: 세션 길이

한 번 접속해서 떠날 때까지의 시간을 계산한다.

- **AC-04** 정상: 세션 종료 기록
  - Given 이용자가 사이트를 연 지 5분이 지났다
  - When 브라우저 탭을 닫거나 다른 앱으로 전환한다
  - Then 세션 종료 기록이 남고, 그 세션의 길이가 약 5분으로 계산된다
- **AC-05** 실패·복구: 종료 기록이 없는 세션
  - Given 종료 기록이 남지 않은 세션(브라우저 강제 종료, 전송 실패)
  - When 지표를 계산한다
  - Then 그 세션의 길이는 세션 안 마지막 기록 시각까지로 계산하고, 결과 화면에 "종료 기록 없음" 세션 수가 따로 보인다

### REQ-03: 도감 수집 진행

팩을 열 때마다 그 시점의 수집 종류 수를 남겨 수집 속도(일수 대비 수집률)를 계산한다. 분모는 항상 전체 카드 수(`MASTER_CARDS.length`)이고 숫자를 고정하지 않는다(DEC-002).

- **AC-06** 정상: 팩 개봉 시 수집 수
  - Given 이용자가 서로 다른 카드 120종을 가지고 있다
  - When 팩을 열어 새 카드 3종을 얻는다
  - Then 그 팩 개봉 기록에 개봉 뒤 수집 종류 수 123이 남는다

### REQ-04: 이용자 분석 지표

기존 024 기록과 REQ-01~03 기록으로 아래 지표를 계산한다. 날짜는 KST로 나눈다.

| 지표 | 정의 |
|---|---|
| 신규 방문자 수 | 기간 안에 첫 기록이 생긴 방문자 수(방문자 ID 기준). 그중 로그인한 수를 따로 보인다 |
| D1·D7 재방문율 | 첫 접속일 기준 1일·7일 뒤(KST 날짜)에 다시 접속한 신규 이용자 비율 [확인 필요: "7일 뒤 그날" 기준인지 "7일 안 아무 날" 기준인지 — 구현 막음: 아니오(기본은 그날 기준)] |
| 첫 팩까지 시간 | 첫 접속부터 첫 팩 개봉까지 걸린 시간의 중앙값 |
| 세션 길이 | 세션 길이의 중앙값과 분포 |
| 화면 이동·이탈 | 화면별 진입 수, 세션의 마지막 화면 분포 |
| 수집 속도 | 첫 접속 후 경과 일수별 수집률 |
| 등급 비율 | 팩 개봉으로 나온 등급별 장수 비율과 `gameConfig.ts`의 설정 확률 비교 |

- **AC-07** 정상: 지표 계산
  - Given 기간 안에 신규 이용자 10명이 있고, 그중 3명이 다음 날 다시 접속했다
  - When 운영자가 그 기간의 지표를 본다
  - Then D1 재방문율 30%와 표본 수 10명이 함께 보인다
- **AC-08** 경계: 표본 부족
  - Given 기간이 시작된 지 7일이 안 됐거나, 해당 신규 이용자가 0명이다
  - When D7 재방문율을 본다
  - Then 숫자 대신 `데이터 부족` 표시와 그 이유(경과 일수 또는 표본 0명)가 보인다. 0%로 표시하지 않는다
- **AC-09** 정상: 등급 비율 비교
  - Given 기간 안에 팩 개봉 기록이 있다
  - When 등급 비율을 본다
  - Then 등급마다 실제 비율, 설정 확률, 표본 장수가 나란히 보인다

### REQ-05: 성능 기록

- **AC-10** 정상: 첫 화면 로딩 지표
  - Given 방문자가 사이트를 연다
  - When 페이지 로딩이 끝나고 이용자가 화면을 쓴다
  - Then 첫 화면 로딩 지표(가장 큰 요소 표시 시간, 입력 반응 시간, 화면 밀림 정도)가 기록되고, 결과 화면에 중앙값과 75번째 백분위가 보인다 [확인 필요: 기기 종류(모바일·데스크톱)로 나눠 볼지 — 구현 막음: 아니오]
- **AC-11** 정상: 3D 팩 화면 성능
  - Given 이용자가 팩 개봉 화면에 들어간다
  - When 3D 팩이 나타나고 개봉 연출이 끝난다
  - Then 3D 화면 준비까지 걸린 시간과 연출 중 평균 프레임(초당 화면 수)이 기록된다
- **AC-12** 대체 흐름: 2D로 바뀜
  - Given WebGL을 쓸 수 없는 기기다
  - When 팩 개봉 화면에 들어간다
  - Then 2D 대체가 일어났다는 기록이 남고, 3D 프레임 기록은 남지 않는다. 결과 화면에 2D 대체 비율이 보인다

### REQ-06: 오류 기록

- **AC-13** 정상: 잡히지 않은 오류
  - Given 이용자 화면에서 처리되지 않은 오류가 난다
  - When 오류가 발생한다
  - Then 오류 종류, 짧은 메시지, 발생 화면, 앱 버전이 기록되고 결과 화면에 종류별 횟수와 영향받은 이용자 수가 보인다. 이메일·닉네임·입력값은 들어가지 않는다 [확인 필요: 메시지 길이 상한과 호출 위치(stack) 보관 여부 — 구현 막음: 아니오]
- **AC-14** 경계: 오류가 반복될 때
  - Given 같은 오류가 한 세션에서 계속 난다
  - When 오류가 100번 반복된다
  - Then 기록은 세션당 정해진 개수를 넘지 않는다 [확인 필요: 세션당 오류 기록 상한 — 영향: AC-14, 무료 쓰기 한도 — 구현 막음: 아니오(plan에서 한도 계산 후 제안)]
- **AC-15** 실패·복구: 오류 기록 자체가 실패
  - Given 오류 기록 쓰기가 실패한다
  - When 오류가 난다
  - Then 기록 실패가 다시 오류 기록을 만들지 않고(무한 반복 없음), 게임은 기존과 같이 동작한다

### REQ-07: 결과 보기

운영자가 REQ-04~06의 지표를 기간별로 본다. 결과는 **운영자 화면(`/#admin`)에 `지표` 탭을 더해** 보여 준다(Q1 답 2026-11-27: "관리자 화면에 추가"). 운영자만 볼 수 있고, 포트폴리오에는 이 화면을 캡처해 넣는다. CSV 내보내기와 공개 지표 페이지는 이번 범위가 아니다.

- **AC-16** 정상: 기간별 지표
  - Given 운영자(DEC-032 계정)
  - When `/#admin`에서 `지표` 탭을 열고 기간을 고른다
  - Then REQ-04~06의 지표가 표본 수와 함께 보인다 [확인 필요: 기간 선택지 — 025는 오늘·7일·30일, 보관 기간은 1년(DEC-033) — 구현 막음: 아니오]
- **AC-17** 권한 오류
  - Given 운영자가 아닌 이용자나 로그인하지 않은 사람
  - When 결과를 열려고 한다
  - Then 지표와 기록이 보이지 않고 `운영자 계정으로 로그인한 뒤 다시 열어 주세요.`가 보인다(025 AC-04와 같음). 기록 읽기는 규칙에서도 거부된다
- **AC-18** 실패·복구
  - Given 기록 불러오기가 실패한다
  - When 결과를 연다
  - Then `기록을 불러오지 못했습니다.`와 다시 시도가 보인다(025 AC-11과 같은 문구)

### REQ-08: 개인정보 고지

## 5. 화면 상태

이용자 화면은 고지 문구 외에 바뀌지 않는다. 아래는 `/#admin`의 `지표` 탭이다. 기존 `행동 로그` 화면은 그대로 두고 탭으로 오간다.

| 상태 | 진입 조건 | 보이는 것 | 가능한 행동 |
|---|---|---|---|
| 권한 없음 | 운영자가 아님 | `운영자 계정으로 로그인한 뒤 다시 열어 주세요.` | 게임으로 돌아가기 |
| 불러오는 중 | 탭을 열거나 기간을 바꿈 | `불러오는 중…`, 기간 버튼 비활성 | 기다리기 |
| 성공 | 기록을 받음 | 이용자 분석(REQ-04), 성능(REQ-05), 오류(REQ-06) 묶음별 표·숫자와 표본 수 | 기간 바꾸기, `행동 로그` 탭으로 가기 |
| 빈 상태 | 기간 안 기록 0건 | `이 기간에 기록이 없습니다.` | 기간 바꾸기 |
| 표본 부족 | 지표별 조건(AC-08) | 그 지표 자리에 `데이터 부족`과 이유 | 기간 바꾸기 |
| 오류 | 불러오기 실패 | `기록을 불러오지 못했습니다.` | `다시 시도` |


- 주요 문구: `데이터 부족`, `종료 기록 없음`, `기록을 불러오지 못했습니다.`, `다시 시도`
- 접근성·반응형: 결과 화면은 025와 같이 휴대폰 폭에서도 표가 가로로 넘치지 않고 스크롤된다

## 6. 품질 요구

- 비용(Firestore 무료 한도: 쓰기 20,000/일, 저장 1 GiB, 읽기 50,000/일 — DEC-031에서 확인)
  - 새 기록 때문에 하루 쓰기가 늘어난다. plan에서 이용자 1명·1세션당 예상 쓰기 수와 하루 최대치를 계산하고, 한도의 절반을 넘으면 모아 쓰기·표본 추출을 쓴다.
  - 결과 화면을 한 번 열 때 읽는 문서 수에 상한을 둔다(025 AC-10과 같은 방식).
- 개인정보: 공통 규칙(4절 머리). 오류 메시지에 계정 ID·이메일이 들어갈 수 있으면 지우고 기록한다.
- 성능: 측정 자체가 개봉 연출 프레임을 떨어뜨리지 않는다. 확인 방법은 plan 6절.
- 보관: [확인 필요: 새 기록의 보관 기간 — 024와 같은 1년(DEC-033)인지 — 구현 막음: 아니오(기본은 1년)]
- 탈퇴: 새 기록 중 계정 ID가 붙은 것은 회원 탈퇴 때 함께 지운다(024 REQ-05와 같음). 계정 ID 없이 방문자 ID만 있는 기록은 누구 것인지 알 수 없어 탈퇴 때 지우지 않고 보관 기간이 지나면 지운다.
- 비로그인 쓰기 보호: 로그인하지 않은 사람도 기록을 쓸 수 있게 되므로, 아무나 대량으로 가짜 기록을 넣거나 남의 기록을 고치지 못해야 한다. 규칙에서 모양·크기를 검사하고 읽기·수정·삭제는 막는다. 확인 방법은 plan 6절(규칙 테스트).
- 오래된 기록 삭제: 024는 본인이 접속할 때 지우지만, 비로그인 기록은 본인 확인이 안 된다. [확인 필요: 비로그인 기록을 1년 뒤 어떻게 지울지 — 운영자 정리 / 같은 브라우저 재방문 시 / TTL(결제 필요) — 구현 막음: 아니오(plan에서 방법 제안)]
- 운영 데이터 보호: `npm run dev`도 운영 Firestore에 연결되므로 localhost에서는 쓰지 않는다.
