## 1. 문제와 목표

혼자 모으는 것만으로는 동기가 오래가지 않는다. 이 기능 이후 로그인 사용자는 랭킹 탭에서 다른 팬과 도감 수집 수를 비교하고, 전종을 완성하면 먼저 완성한 순서대로 위에 오른다. 업적 카테고리를 모두 달성하면 닉네임 옆에 배지가 붙는다.

## 2. 범위

- 포함: 랭킹 문서 갱신(저장·로그인 시), Top 50 조회, 정렬 규칙, 수집률 재계산, 1위 강조, 내 순위 강조, 배지 표시, 새로고침, 운영자·게스트·테스트 계정 제외, 봇 53명 혼합
- 제외: 배지 공유 이미지 — 기능 020 / 업적 판정 — 기능 009 / 상대 프로필 상세 모달(`LeaderboardModal`, 진입 버튼 없음)
- 선행 조건: 기능 008(저장 시 갱신), 기능 009(배지)

## 3. 사용자 흐름

1. 랭킹 탭(`RANKING`, 모바일 `RANK`)을 연다.
2. `실시간 랭킹 데이터를 집계하고 있습니다...` 후 Top 50 목록이 보인다. 1위는 위에 크게 보인다.
3. 각 줄에 순위(1~3위 메달), 아바타, 닉네임, 배지, 수집률, 개봉 팩 수가 보인다. 내 줄에는 `나`와 `공유`가 있다.
4. `실시간 순위 새로고침`으로 다시 불러온다.
5. 팩을 열고 돌아오면(또는 새로고침하면) 내 순위가 반영되어 있다.

## 4. 요구사항과 인수 조건(AC)

### REQ-01: 순위 규칙

고유 카드 수 내림차순. 둘 다 전종(`≥ MASTER_CARDS.length`)이면 `fullCollectionAt`이 이른 쪽이 위. 그 외 동률은 조회 순서를 유지한다(DEC-018).

- **AC-01** 정상: 많이 모은 사람이 위다
  - Given A 300종, B 250종
  - When 랭킹을 연다
  - Then A가 B보다 위다
- **AC-02** 경계: 전종 동률은 먼저 완성한 사람이 위다
  - Given A·B 모두 521종, A의 `fullCollectionAt`이 B보다 이르다
  - When 랭킹을 연다
  - Then A가 B보다 위다
- **AC-03** 완성 시각 고정: 한 번 기록되면 바뀌지 않는다
  - Given `fullCollectionAt`이 있는 A
  - When A가 팩을 더 열어 저장된다
  - Then `fullCollectionAt` 값이 그대로다
- **AC-04** 이전 완성자 이관
  - Given 기능 도입 전 이미 521종이고 `fullCollectionAt`이 없는 문서
  - When 그 사용자가 저장한다
  - Then 기존 `updatedAt` 값이 `fullCollectionAt`으로 한 번 옮겨진다

### REQ-02: 등록 대상

- **AC-05** 정상: 로그인 사용자가 저장하면 랭킹 문서가 갱신된다
  - Given 구글 로그인 사용자
  - When 팩을 연다
  - Then `nmixx_tcg_leaderboard/<uid>`의 `uniqueCardCount`, `collectionRate`, `totalPacksOpened`, `coins`, `hasXR`, `achievementBadges`, `updatedAt`이 갱신된다
- **AC-06** 제외: 게스트·운영자는 등록되지 않는다
  - Given 게스트 또는 운영자 계정(DEC-012)
  - When 팩을 연다
  - Then 랭킹 목록에 나오지 않는다(운영자 본인이 저장할 때 자기 랭킹 문서를 지운다, DEC-012. 다른 사람이 조회할 때는 지우지 않는다, AC-11)

### REQ-03: 표시

- **AC-07** 정상: 수집률은 현재 카드 수로 다시 계산한다(DEC-016)
  - Given 저장된 `collectionRate`가 잘못된 문서(예: 651 기준)
  - When 랭킹 탭을 본다
  - Then 수집률이 `uniqueCardCount / 521`로 표시된다
- **AC-08** 정상: 내 줄 강조와 배지
  - Given 업적 카테고리 `PACKS`를 모두 달성한 로그인 사용자
  - When 랭킹을 본다
  - Then 내 줄에 `나` 표시와 📦 배지가 보인다
- **AC-09** 빈 상태
  - Given 실제 사용자 문서가 없고 Firestore 연결이 안 됨
  - When 랭킹을 연다
  - Then 봇 53명 중 상위 50명이 보인다 (봇 때문에 빈 목록은 실제로 나오지 않음)
- **AC-10** 실패·복구: 조회 실패
  - Given Firestore 조회가 실패
  - When 랭킹을 연다
  - Then 봇만으로 목록이 보이고 오류 창은 없다. `실시간 순위 새로고침`으로 다시 시도할 수 있다

### REQ-04: 조회는 데이터를 지우지 않는다

2026-11-10 `/sdd-change`로 추가했다(DEC-023). 랭킹 조회는 누구나 하므로, 조회 경로에서 다른 사용자의 문서를 지우면 안 된다.

- **AC-11** 테스트·운영자 판정 문서는 숨기기만 한다
  - Given uid가 `mock_`으로 시작하는 랭킹 문서와 그 uid의 유저 문서
  - When 아무 사용자가 랭킹을 연다
  - Then 그 문서는 목록에 없고, Firestore의 랭킹 문서와 유저 문서는 그대로 남아 있다
- **AC-12** 카카오 기본 닉네임 사용자도 랭킹에 오른다
  - Given `displayName`이 `카카오_엔써_ab12`인 로그인 사용자의 랭킹 문서
  - When 다른 사용자가 랭킹을 연다
  - Then 수집 수에 맞는 순위로 목록에 보이고, 그 사용자의 랭킹·유저 문서는 그대로 남아 있다
