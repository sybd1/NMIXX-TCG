## 1. 문제와 목표

2026-11-26부터 Firestore 규칙이 "Firebase 인증을 받은 문서 주인만 쓸 수 있다"로 바뀌었다(기능 022, DEC-028). 그런데 카카오 로그인은 Firebase 인증을 거치지 않는다(DEC-008). 그래서 카카오 사용자(운영 11명)는 지금 클라우드 저장·불러오기·랭킹 등록·탈퇴 시 클라우드 삭제를 할 수 없고, 진행이 한 기기의 로컬 저장에만 남는다.

이 기능이 끝나면 다음이 성립해야 한다.

- 카카오로 로그인한 사용자가 기존 계정 ID `kakao_<카카오 회원번호>`의 주인으로 Firebase에 인증된다.
- 구글 사용자와 똑같이 자기 문서를 저장·불러오기·랭킹 등록·삭제할 수 있다.
- 다른 사람이 카카오 사용자를 사칭해 그 문서를 쓸 수는 없다.

## 2. 범위

- 포함:
  - 카카오 로그인 성공 직후, 카카오가 인정한 회원번호를 확인해 그 회원번호에 해당하는 Firebase 인증을 받는 흐름
  - 이 확인은 브라우저가 아닌 곳에서 해야 한다. 브라우저가 보낸 회원번호를 그대로 믿으면 누구나 남을 사칭할 수 있다.
  - 새로고침·재방문 시 카카오 사용자의 Firebase 인증 유지
  - 이미 카카오로 로그인되어 있던 기존 사용자(로컬 세션만 있고 Firebase 인증이 없는 상태)를 다시 연결하는 흐름(REQ-04)
  - 다시 연결할 때 더 최근 진행을 남기기(REQ-05)
  - 카카오 사용자의 Firebase 세션이 구글 계정으로 잘못 처리되지 않게 하기(REQ-03)
  - 카카오 사용자 탈퇴 시 클라우드 문서와 Firebase 인증 계정 삭제
  - 카카오 SDK가 없을 때 무작위 ID로 "로컬 전용 카카오 계정"을 만들던 대체 동작을 없애고 로그인 실패로 처리하기(REQ-08, Q-D)
  - 구조 결정 기록: DEC-001(자체 서버 없음)과 DEC-008(카카오는 Firebase 인증 미사용)을 대체하는 새 DEC
- 제외:
  - Firestore 규칙 변경 — 기능 022의 규칙(DEC-027 계약: 인증 uid = 문서 ID `kakao_<회원번호>`, 로그인 방식 = 커스텀)을 그대로 쓴다.
  - 카카오 SDK 버전 교체, 로그인 화면 디자인 변경
  - 카카오 연결 끊기(카카오 계정에서 앱 연결 해제) — 기존 탈퇴 범위를 유지한다.
  - 구글 로그인 흐름 변경(REQ-03의 오인 방지는 제외)
- 선행 조건:
  - 기능 007(로그인), 008(저장·동기화), 022(규칙 운영 배포 완료)
  - 운영자 준비: Firebase 프로젝트 `nmixx-tcg`의 커스텀 토큰을 발급할 수 있는 서버용 자격 증명, 카카오 앱 설정 정보. 보관 위치와 방법은 plan에서 정한다. 저장소에 커밋하지 않는다.

## 3. 사용자 흐름

1. 로그인 창에서 `카카오 계정으로 시작`을 누른다. 버튼이 `카카오 계정 연결 중...`으로 바뀐다(기존과 같음).
2. 카카오 팝업에서 동의하면, 앱이 카카오 회원번호를 확인받고 Firebase 인증을 받는다. 이 동안 연결 중 상태가 유지된다.
3. 성공하면 기존처럼 닉네임이 헤더에 보인다. 클라우드에 진행이 있으면 불러오고, 이후 상태 변경은 클라우드와 랭킹에 저장된다.
4. 새로고침하거나 다음 날 다시 와도 카카오 사용자로 남아 있고, 저장이 계속된다.
5. 실패 처리: 회원번호 확인이나 Firebase 인증이 실패하면 로그인이 끝나지 않는다. `카카오 계정 확인에 실패했습니다. 잠시 후 다시 시도해 주세요.`가 보이고 다시 시도할 수 있다(Q-B).

## 4. 요구사항과 인수 조건(AC)

> 용어
> - **카카오 인증 연결**: 카카오 로그인 결과를 확인해, 문서 ID `kakao_<회원번호>`의 주인으로 Firebase 인증을 받는 것.
> - **기존 카카오 세션**: 이 기능 전에 로그인해서 브라우저에 카카오 계정 세션은 있지만 Firebase 인증은 없는 상태.

### REQ-01: 카카오 로그인 시 본인 계정으로 Firebase 인증을 받는다

카카오가 확인해 준 회원번호로만 인증한다. 브라우저가 보낸 회원번호나 프로필 값은 믿지 않는다. 인증된 사용자의 ID는 기존과 같은 `kakao_<회원번호>`여야 한다. 그래야 기존 문서·랭킹·컬렉션 키가 유지된다(DEC-002와 같은 이유).

- **AC-01** 정상: 새 기기에서 카카오 로그인 후 저장
  - Given 운영 Firestore에 `nmixx_tcg_users/kakao_K`가 있는 카카오 사용자 K, 저장본이 없는 브라우저
  - When `카카오 계정으로 시작` → 동의 → 팩 1개 개봉
  - Then 헤더에 K의 닉네임이 보이고, 도감·코인이 클라우드 값으로 보인다(008 AC-04). `kakao_K` 문서의 `lastSavedAt`과 `nmixx_tcg_leaderboard/kakao_K`가 갱신되고, 브라우저 콘솔에 `permission-denied`가 없다
- **AC-02** 정상: 처음 가입하는 카카오 사용자
  - Given Firestore에 문서가 없는 카카오 계정
  - When 카카오로 로그인하고 팩을 연다
  - Then `nmixx_tcg_users/kakao_<회원번호>`와 랭킹 문서가 생긴다. 다른 ID(예: `goog_…`)의 문서는 생기지 않는다
- **AC-03** 권한 오류: 사칭 시도
  - Given 공격자가 다른 사람의 카카오 회원번호 J를 안다
  - When 자기 카카오 로그인 결과 대신 J를 내세우거나, 위조·만료된 카카오 토큰으로 인증을 요청한다
  - Then 인증이 거부되어 `kakao_J`로 Firebase에 로그인되지 않는다. `nmixx_tcg_users/kakao_J`는 그대로다
- **AC-04** 실패·복구: 인증 단계 실패 (Q-B, 2026-11-26 확정: 로그인 실패로 처리)
  - Given 카카오 팝업은 성공했지만 회원번호 확인 또는 Firebase 인증이 실패한다(서버 응답 없음, 네트워크 끊김 등)
  - When 사용자가 로그인을 시도한다
  - Then 로그인이 끝나지 않고 로그인 창에 `카카오 계정 확인에 실패했습니다. 잠시 후 다시 시도해 주세요.`가 보이며, `카카오 계정으로 시작`을 다시 누를 수 있다. 카카오 세션이 만들어지지 않으므로 헤더에 닉네임이 보이지 않는다. 클라우드 문서는 바뀌지 않는다

### REQ-02: 새로고침·재방문 후에도 인증이 유지된다

- **AC-05** 정상: 새로고침
  - Given AC-01 상태
  - When 새로고침하고 팩을 1개 더 연다
  - Then 카카오 사용자 K로 남아 있고 `kakao_K` 문서가 다시 갱신된다. 로그인 창이 다시 뜨지 않는다
- **AC-06** 경계: 오래 지난 재방문
  - Given AC-01 뒤 브라우저를 닫고 [확인 필요: Q-C 기준 기간] 뒤 다시 연다
  - When 팩을 연다
  - Then 저장이 성공한다. 인증이 만료되었다면 다시 로그인하라는 안내가 보이고, 그동안 클라우드 문서는 바뀌지 않는다

### REQ-03: 카카오의 Firebase 세션을 구글 계정으로 처리하지 않는다

현재 앱은 Firebase 로그인 상태를 받으면 모두 구글 계정(`goog_` 접두어)으로 처리한다.

- **AC-07** 회귀 방지: 계정이 바뀌지 않는다
  - Given AC-01 상태
  - When 새로고침이나 Firebase 인증 상태 갱신이 일어난다
  - Then 세션 계정 ID는 `kakao_K`, 제공자는 `kakao`로 유지된다. `goog_kakao_…` 같은 사용자 문서나 랭킹 문서가 생기지 않는다
- **AC-08** 회귀 방지: 구글 로그인은 그대로다
  - Given 구글 사용자 A
  - When 로그인 → 팩 개봉 → 새로고침
  - Then 기존과 같이 `goog_A` 문서에 저장되고 화면도 같다(007 AC, 008 AC-01)

### REQ-04: 기존 카카오 세션을 다시 연결한다

운영에는 이 기능 전에 로그인한 카카오 사용자가 있다. 이들의 브라우저에는 카카오 세션만 있고 Firebase 인증은 없다.

연결 방식(Q-A, 2026-11-26 확정): 사이트를 열 때, 브라우저에 남은 카카오 로그인 토큰으로 먼저 자동 연결을 시도한다. 토큰이 없거나 만료되어 자동 연결을 할 수 없으면 다시 로그인하라는 안내를 보여 준다.

- **AC-09** 정상: 자동 재연결
  - Given 기존 카카오 세션이 있고, 카카오 로그인 토큰이 아직 유효한 브라우저
  - When 사이트를 연다
  - Then 사용자가 아무것도 누르지 않아도 연결된다. 진행은 REQ-05 규칙대로 남고, 이후 팩 개봉이 `kakao_K` 문서와 랭킹에 저장된다
- **AC-09a** 정상: 토큰이 없을 때 안내
  - Given 기존 카카오 세션은 있지만 카카오 로그인 토큰이 없거나 만료된 브라우저
  - When 사이트를 연다
  - Then `클라우드 저장을 위해 카카오로 다시 로그인해 주세요.` 안내가 보인다. 안내에서 카카오 로그인을 마치면 AC-09와 같이 연결된다. 안내를 닫고 계속 플레이하면 로컬에만 저장된다(AC-10)
- **AC-10** 실패·복구: 재연결 실패
  - Given AC-09에서 자동 연결이 실패하거나(서버 오류 등), AC-09a 안내를 닫았다
  - When 사용자가 계속 플레이한다
  - Then 로컬 저장은 계속되고 `클라우드 저장을 위해 카카오로 다시 로그인해 주세요.` 안내가 다시 볼 수 있는 곳에 남는다(위치는 plan에서 정함). 클라우드 문서는 바뀌지 않는다

### REQ-05: 다시 연결할 때 더 최근 진행을 남긴다

현재 앱은 로그인할 때 클라우드에 진행이 있으면 그것으로 화면 상태를 덮는다(008). 카카오 사용자는 2026-11-26 규칙 배포(DEC-028)부터 로컬에만 진행이 쌓였다. 그래서 다시 연결하면 그 기간의 진행이 더 오래된 클라우드 값에 덮일 수 있다.

규칙(Q-E, 2026-11-26 확정)
- 카카오 사용자가 연결될 때, 이 기기의 로컬 진행과 클라우드 진행 중 **마지막 저장 시각이 더 늦은 쪽**을 남긴다. 남긴 진행을 화면과 클라우드 문서에 같이 반영한다.
- 로컬 저장본은 앞으로 저장 시각을 함께 남긴다.
- 저장 시각이 없는 기존 로컬 저장본은 다음처럼 판단한다. 클라우드 `lastSavedAt`이 규칙 배포 시각(`2026-11-25T15:13:46.798Z` = 11-26 00:13 KST, DEC-028의 ruleset 게시 시각) **이전**이면 로컬이 더 최근이다. **이후**이면 클라우드가 더 최근이다. 클라우드가 그 이후에 저장되었다는 것은 다른 기기에서 이미 연결되었다는 뜻이기 때문이다.
- 클라우드 문서가 없거나 진행 필드가 없으면 로컬을 남긴다.
- 이 규칙은 카카오 사용자의 연결 시점에만 적용한다. 구글 사용자의 로그인 동작(008)은 바꾸지 않는다.

- **AC-11** 데이터 보존: 클라우드 저장이 멈춘 동안의 로컬 진행
  - Given 카카오 사용자 K. 클라우드 `kakao_K`의 `lastSavedAt`은 2026-10-31(도감 100종). 이 기기의 로컬 저장본은 저장 시각이 없고 도감 120종
  - When K가 같은 기기에서 연결된다
  - Then 화면 도감이 120종이고, `kakao_K` 문서의 `collection`이 120종으로 바뀐다
- **AC-11a** 경계: 다른 기기에서 이미 연결된 경우
  - Given K가 기기 B에서 연결되어 클라우드 `lastSavedAt`이 2026-11-27(도감 130종). 기기 A의 로컬 저장본은 저장 시각이 없고 도감 120종
  - When K가 기기 A에서 연결된다
  - Then 화면 도감이 130종이고, 클라우드 문서는 130종 그대로다
- **AC-11b** 정상: 저장 시각이 있는 두 진행
  - Given 로컬 저장 시각이 클라우드 `lastSavedAt`보다 늦다(또는 이르다)
  - When K가 연결된다
  - Then 더 늦은 쪽의 도감·코인이 화면과 클라우드 문서에 같이 보인다
- **AC-12** 경계: 다른 기기에서 처음 연결
  - Given K의 로컬 저장이 없는 다른 기기
  - When 연결한다
  - Then 클라우드 값으로 시작한다(008 AC-04와 같음)

### REQ-06: 카카오 사용자 탈퇴

- **AC-13** 정상: 탈퇴하면 클라우드와 인증 계정이 지워진다
  - Given 연결된 카카오 사용자 K
  - When 정보 탭에서 회원 탈퇴를 한다(기능 014)
  - Then `nmixx_tcg_users/kakao_K`·`nmixx_tcg_leaderboard/kakao_K`가 사라지고, K의 Firebase 인증 계정도 지워진다. 다른 문서는 바뀌지 않는다
- **AC-14** 실패·복구: 연결되지 않은 상태의 탈퇴
  - Given 기존 카카오 세션만 있고 연결되지 않은 K
  - When 탈퇴를 누른다
  - Then 탈퇴가 진행되지 않고 `클라우드 저장을 위해 카카오로 다시 로그인해 주세요.` 안내가 보인다(Q-F: 먼저 재연결). 연결을 마친 뒤 다시 탈퇴하면 AC-13대로 처리된다. 로컬·클라우드 데이터는 연결 전까지 그대로다

### REQ-08: 카카오 SDK가 없으면 로그인 실패로 처리한다

지금 앱은 카카오 SDK가 로드되지 않거나 초기화에 실패하면, 무작위 ID로 "로컬 전용 카카오 계정"을 만든다. 이 계정은 확인할 카카오 회원번호가 없어 클라우드에 저장할 수 없고, 다시 로그인하면 다른 계정이 된다(Q-D, 2026-11-26 확정: 오류로 바꾼다).

- **AC-17** 실패·복구: SDK 없음
  - Given 카카오 SDK를 불러오지 못한 브라우저(예: 스크립트 차단)
  - When `카카오 계정으로 시작`을 누른다
  - Then 로그인이 끝나지 않고 `카카오 계정 확인에 실패했습니다. 잠시 후 다시 시도해 주세요.`가 보인다. 새 `kakao_…` 세션이나 Firestore 문서가 만들어지지 않는다. 구글 로그인과 게스트 시작은 그대로 쓸 수 있다

### REQ-07: 운영 반영과 기록

- **AC-15** 결정 기록
  - Given 이 기능이 서버 측 처리(카카오 확인·인증 발급)를 들인다
  - When 구현을 시작하기 전
  - Then DEC-001·DEC-008을 대체하는 새 DEC가 `docs/decisions.md`에 있다. 서버 측 처리의 범위(이 기능의 인증 발급만), 자격 증명 보관 방법, 비용이 적혀 있다
- **AC-16** 운영 확인
  - Given 운영 배포 후
  - When 실제 카카오 테스트 계정으로 AC-01·05·07을 운영 사이트에서 확인한다
  - Then 모두 통과하고 결과가 product.md Q-02 또는 이 기능의 검증 기록에 남는다
