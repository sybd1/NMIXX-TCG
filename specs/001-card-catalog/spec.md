# Spec 001: 카드 카탈로그와 등급 체계

- 상태: Implementing  <!-- 코드 배포됨, 검증 기록 미완 -->
- 최종 수정일: 2026-11-10
- 제품 문서: [docs/product.md](../../docs/product.md) 기능 001
- 디자인 자료: 없음 — 등급 색상은 `RARITY_CONFIGS`, 가공 효과는 `FINISH_CONFIGS`

## 1. 문제와 목표

수집 게임은 "무엇을 모으는가"가 먼저 정해져야 한다. 이 기능은 NMIXX 부스터 팩 5종의 카드 목록, 9단계 등급, 등급별 가공(포일) 효과를 정의한다. 이후 팩 추첨·도감·업적·랭킹은 모두 이 카탈로그를 기준으로 계산한다.

## 2. 범위

- 포함: 카드 데이터 형식, 팩 5종(NX-01~NX-05)과 히든 카드 1장, 등급 9단계와 확률·더스트 값, 등급별 가공 효과, 카드 한 장의 화면 표현(`CardVisual`, `CardModal`)
- 제외: 추첨 알고리즘 — 기능 002 / 도감 필터 — 기능 004 / 세트 보상 — 기능 005
- 선행 조건: 없음

## 3. 사용자 흐름

1. 사용자가 개봉 화면이나 도감에서 카드를 본다.
2. 카드 앞면에 멤버 사진, 이름, 등급 배지, 일련번호(`NX1-001` 형식)가 보이고, 등급이 높을수록 포일·광택·입자 효과가 강해진다.
3. 마우스를 올리면 카드가 기울고 빛이 움직인다.
4. 카드를 누르면 상세 창에 번호·멤버·시대(era)·출현 팩·가공 이름·보유 수가 보인다.
5. 아직 없는 카드는 `🔒 LOCKED`로 보이고, XR 미스터리 카드는 정체가 가려진다.

## 4. 요구사항과 인수 조건(AC)

### REQ-01: 카탈로그 구성

카드 `id`는 전체에서 유일하다. 모든 카드는 `public/` 아래에 실제로 있는 이미지 경로를 가진다(대소문자 일치). 도감 총수는 카드 배열 길이로 계산한다(DEC-002).

- **AC-01** 정상: 도감 총수는 데이터 장수와 같다
  - Given `op01~op05.json`과 `special.json`에 각각 128·114·123·86·69·1장
  - When 도감 탭을 연다
  - Then "총 521장의 NMIXX 공식 카드 중 …" 문구와 진행률 분모가 521이다
- **AC-02** 입력 오류: 이미지 경로가 틀린 카드가 있으면 배포되지 않는다
  - Given 카드 JSON의 `image`가 `public/`에 없는 파일이거나 대소문자가 다르다
  - When `npm run build`를 실행한다
  - Then `❌ [BUILD GUARD ERROR] Missing image file` 또는 `Case mismatch`를 출력하고 종료 코드 1로 멈춘다
- **AC-03** 경계: 카드 `id`가 중복되지 않는다
  - Given 전체 카드 데이터
  - When `id` 목록을 센다
  - Then 고유 `id` 수가 카드 수(521)와 같다

### REQ-02: 등급과 가공

등급은 C·UC·R·SR·SSR·UR·LR·MR·XR 9단계. 확률·분해·제작 값은 plan 3절 원본을 따른다(DEC-003). 가공은 등급마다 하나로 정해진다.

- **AC-04** 정상: 등급별 시각 효과가 다르다
  - Given 보유한 C 카드와 MR 카드
  - When 둘을 큰 크기로 본다
  - Then C는 반사 없는 무광, MR은 오로라 색 변화와 입자 4개가 보인다
- **AC-05** 경계: 미보유 카드는 효과 없이 잠금 표시된다
  - Given 보유하지 않은 SSR 카드
  - When 도감에서 본다
  - Then 반투명·흑백(grayscale 80%) 처리와 `🔒 LOCKED`가 보이고 포일·광택이 없다
- **AC-06** 비밀: XR 카드는 보유 전 정체를 숨긴다
  - Given XR 카드를 보유하지 않음
  - When XR 카드 앞면을 본다(도감 XR 배너)
  - Then 사진·이름 대신 `?`, `XR 초월`, `TRANSCENDENT CARD`, `전체 카드 수집 시 자동 획득`이 보인다
  - 그리고 상세 창이 열리는 경우 이름은 `[XR] 초월 카드`, 멤버는 `???`로 보인다

### REQ-03: 카드 상세

- **AC-07** 정상: 상세 창에 카드 정보가 보인다
  - Given 보유한 카드
  - When 카드를 누른다
  - Then 번호, 등급, 멤버, 시대, 출현 팩(`📦 출현 카드팩`), 가공 이름, `소장 중 (x{n}장 보유)`가 보인다
  - 그리고 SR 이상이면 멤버 멜로디가 재생되고 `🎵 멜로디 듣기` 버튼이 있다
- **AC-08** 실패·복구: 이미지를 못 불러오면 대체 경로를 시도한다
  - Given 이미지 요청이 실패한다
  - When 카드가 그려진다
  - Then 앞의 `/`를 뺀 경로로 한 번 더 시도하고, 그래도 실패하면 이미지 영역만 숨기고 나머지 정보는 보인다

## 5. 화면 상태

| 상태 | 진입 조건 | 보이는 것 | 가능한 행동 |
|---|---|---|---|
| 보유 | `collection[id] ≥ 1` | 컬러 이미지, 등급 효과, `xN` 수량 배지 | 누르면 상세 |
| 미보유 | `collection[id]` 없음 | 흑백, `🔒 LOCKED` | 누르면 상세(미보유 표시) |
| XR 미보유 | XR이고 미보유 | `?`, `XR 초월`, `TRANSCENDENT CARD` | 도감 목록에서는 숨김 |
| 신규 | 이번 개봉에서 처음 얻음 | `NEW` 배지 | - |

- 주요 문구: `🔒 LOCKED`, `소장 중 (x{n}장 보유)`, `미보유 (LOCKED)`, `닫기 (CLOSE)`
- 접근성·반응형: 카드 크기 `sm`/`md`/`lg`. 이미지 `alt`는 카드 이름(XR 미보유는 `초월 카드`). 상세 창에는 자체 ESC 처리가 없고, ESC를 누르면 앱 전역 처리(`App.tsx`)가 팩 탭으로 이동시켜 창이 함께 사라진다(기능 003 7절).

## 6. 품질 요구

- 카드 기울기 계산은 `requestAnimationFrame`으로 묶어 60fps를 유지한다(v1.5.1).
- 카드 이미지는 `.webp`, Vercel에서 30일 캐시(DEC-021).

## 7. 미결 질문

- 알려진 한계: JSON의 `finishType`이 등급과 다른 카드가 203장 있다. 팩에서 뽑힐 때는 `RARITY_TO_FINISH`로 덮어쓰지만, 도감은 JSON 값을 쓴다. [확인 필요: JSON 값을 등급 기준으로 일괄 정리할지 — 구현 막음: 아니오]
- 알려진 한계: JSON의 `dustValue`가 `RARITY_CONFIGS[].dustDismantle`과 다른 카드가 251장 있다. 분해 계산은 `RARITY_CONFIGS`를 쓰므로 `dustValue`는 사용되지 않는다.
- 알려진 한계: `collectionNumber`가 고유하지 않다(521장 중 129개 값). 일련번호 표시에만 쓰고 정렬 기준으로는 부정확하다.
- 알려진 한계: 팩 텍스처의 "전 N종" 문구는 `BOOSTER_PACKS[].totalCards`(134/119/126/89/69)를 써서 실제 장수와 다르다 (product.md Q-04).
